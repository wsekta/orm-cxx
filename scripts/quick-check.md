# Quick local checks

Run `python scripts/quick-check.py` from a feature worktree before pushing. The default base is `origin/main`; refresh it first. Pass `--base REF` for a different agreed base. Changed tracked, staged, and non-ignored untracked files are included in file selection. The diff check covers tracked changes; inspect untracked files in the diff review. Files that have both staged and unstaged changes are rejected because the working file would not represent the staged commit; stage or unstage each such file before checking.

The script checks changed C++ files with `clang-format` 18 and changed project CMake files with `cmake-format` 0.6.13. It excludes third-party files as the CI formatter does. For C++ or CMake changes it configures and builds the `orm-cxx` target using a local compiler. On Windows the default is `msvc-debug` in an MSVC developer environment. On Linux it selects `linux-clang-debug` if Clang 18 is installed, otherwise `linux-gcc-debug` if GCC 15 is installed. Use `--preset NAME` to select a suitable checked-in configure/build/test preset. The script checks inherited compiler and submodule requirements in `CMakePresets.json`; it cannot resolve user-only presets. Submodules and dependencies must already be available; the script does not install them.

Choose relevant tests with `--test-regex REGEX`. This builds `orm-cxx-UT` and invokes CTest with the regex; no matching tests is a failure. The test binary can be expensive to build in a fresh worktree. Without a regex, tests are explicitly reported as skipped, not passed. A build with no selected tests does not establish that changed tests compile.

Full `scripts/check-tidy.sh` builds the `quality` preset and is not a cheap check. For changed source files, `--tidy-build build/quality` runs `clang-tidy` 18 only against matching entries in an existing compilation database. The operator must first ensure the database and module BMIs were built for the current worktree and source state with Clang 18. Headers and sources without direct compilation entries are reported as not covered. If these prerequisites are absent, clang-tidy is skipped and CI remains the full analysis gate.

Each applicable check reports `PASS`, `FAIL`, or `SKIP`. A failed command returns a nonzero exit status and blocks the push; a missing tool or unavailable prerequisite is reported as `SKIP` and produces an `INCOMPLETE` summary. Record skipped checks in the task or PR. A zero exit status with `INCOMPLETE` does not mean all checks passed. The ten-minute target applies to a warm environment and is not enforced by killing a running check. Cold setup and dependency builds may take longer.
