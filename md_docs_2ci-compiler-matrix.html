Tested Compiler Versions

Linux CI uses Ubuntu 24.04 (Noble) runners. GCC jobs run inside the official gcc:15-trixie image; Clang jobs install compiler packages from the Ubuntu repositories. Linux package-manager jobs use Clang 18.

GCC

Version Package Workflow Status
GCC 15 gcc-15 / g++-15 linux-gxx-build.yml Tested

GCC 15.3.0 and 16.2.0 were validated with the full module build. GCC 14 exceeds its imported source-location limit. GCC 15 and 16 require -fno-module-lazy on both module producers and importers to avoid Bad file data from the lazy reader; both CMake targets propagate this option, including installed interfaces rebuilt by consumers.

The GCC workflow also installs ORM and SOCI into an isolated prefix and builds the find_package consumer with warnings treated as errors. A separate installed reflection consumer disables SOCI discovery. Both checks rebuild their module interfaces using the targets' public options and then run the resulting programs.

Backend and consumer matrix

postgresql-build.yml runs all four adapters through the same conformance suite. The workflow name is Backend conformance. Clang 18, 19 and 20 and GCC 15 cover PostgreSQL 15/18, MySQL 8.4/9.7 and MariaDB 11.4/11.8/12.3. MSVC builds every adapter; live server tests run on Linux. Each all-adapter build registers consumers for all 16 independent subsets. Every consumer checks exact registry membership and compiles negative controls for disabled provider types. Core compiler jobs require no database clients.

The Packages workflow repeats the 16 subsets for Conan and vcpkg on Linux and Windows. Linux installed consumers run live CRUD and migrations against every selected service; Windows verifies module, provider and linking contracts.

Coverage policy

Clang 18 produces five independent reports: core, SQLite, PostgreSQL, MySQL and MariaDB. The backend conformance workflow merges the full report list and requires 100% line coverage. Every adapter contributes under the same policy.

The LLVM exporter removes compiler-synthesized implicit-member maps only when every zero-count region exactly covers a class name on a plain class or struct declaration line in a project module, and LLVM profdata has no instrumentation record for that function. It verifies that all profile records were read. Explicit method bodies and instrumented functions with zero hits remain coverage failures. The exporter reports how many maps and declaration lines it normalized. Python is required only for coverage builds.

The merged report is uploaded with Codecov flag all-backends; the standalone core compiler workflow also uploads its core report.

CMake Presets

Each compiler version has dedicated CMake presets. All library and consumer builds use native C++20 modules through Ninja 1.11+ and CMake 3.31+. CI installs CMake 3.31.6 and Ninja 1.13.0 explicitly. The default GCC presets select GCC 15; Clang 18 remains the coverage compiler.

Adding New Compiler Versions

To add a new compiler version to CI:

  1. Verify module scanning, module ownership, and consteval/constexpr support
  2. Build and install both modules, then run a relocated installed consumer
  3. Add new CMake presets in CMakePresets.json (configure, build, test, workflow)
  4. Add a new job in the relevant workflow in .github/workflows/
  5. Update this document with the new version
  6. If the new version should collect coverage, update the coverage policy section
